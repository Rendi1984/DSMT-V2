Before you start

This wizard configures a fresh DSMT installation. It takes two things:

Step 2 A SQL Server you can create a database on

DSMT stores its configuration and audit trail here. The account you provide needs the dbcreator server role, or an existing database it can write to.

Step 3 A directory account that can read your domain

Used to look up users. Any ordinary domain account is normally enough — DSMT only reads. Plain LDAP works out of the box; LDAPS is available if your domain controllers have certificates installed.

Sign-in is not implemented yet, so DSMT listens on localhost only. Do not expose it to the network until authentication ships.

Directory

The domain controller DSMT reads users from.

Connection
Domain
Your Active Directory domain — not the controller's hostname. DSMT builds the base DN from it.
Filled in from the domain above. Narrow it to search one OU only, for example OU=Staff,DC=contoso,DC=local.
Bind account
Any of three forms works: CONTOSO\svc_dsmt, svc_dsmt@contoso.local, or a full DN such as CN=svc_dsmt,OU=Service,DC=contoso,DC=local. A bare username is completed using the domain above. Non-AD LDAP servers usually require the full DN. The password is stored encrypted. DSMT only reads the directory — no write permission is needed.
