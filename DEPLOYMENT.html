1. What you are deploying

DSMT is a web front end for looking up Active Directory users. You install it through a browser-based wizard, and from then on it reads the directory live — user data is never copied into a database.

ComponentWhat it is
Web front endStatic HTML and JavaScript. No build step, no framework.
ServerA single Node.js process (server/index.js) running Express.
SQL ServerHolds configuration and the audit log only. No user data is mirrored.
DirectoryRead over LDAP or LDAPS. DSMT only reads — it never writes to AD.

What this release does

  • Browser-based setup wizard: creates the SQL Server database and stores the directory connection.
  • Feature 1 — user lookup: searchable user list read live from the domain controller, per-user detail, and group membership including nested groups.
No sign-in yet

This release has no authentication. Anyone who can reach the port can read your directory. DSMT therefore listens on 127.0.0.1 only by default. See section 9 before changing that.

2. Before you start

Collect these before running the wizard — it will ask for all of them.

On the machine that will run DSMT

  • Node.js 20 or later. Check with node --version.
  • Network access to your SQL Server and to a domain controller.
  • Roughly 100 MB of disk space.

SQL Server

  • Hostname or IP, and the port (usually 1433) — or the instance name if it is a named instance.
  • A login DSMT can use — or nothing at all: leave the username and password blank in the wizard and DSMT connects as the Windows account it is running as (Integrated Authentication). SQL Server Authentication and explicit Windows Authentication (NTLM) also work.
  • That login needs the dbcreator server role to create the database. Alternatively, create an empty database yourself and give the login write access to it.
  • TCP/IP enabled in SQL Server Configuration Manager.
  • For a named instance: the SQL Browser service running, and UDP 1434 open.

Active Directory

  • A domain controller hostname or IP.
  • Your domain name, for example contoso.local.
  • A bind account and password. Any ordinary domain user is normally enough — DSMT only reads. Unlike the database step, these are required; see the note below.
  • Port 389 open for LDAP, or 636 if you want LDAPS.
  • For LDAPS: certificates installed on your domain controllers.
Use LDAPS if you can

Plain LDAP sends the bind password over the network unencrypted. If your domain controllers have certificates, tick Use LDAPS in the wizard.

3. Install and run

  1. Unpack

    Extract the release ZIP to where DSMT will live, for example C:\DSMT or /opt/dsmt.

  2. Install dependencies

    If the ZIP already contains a node_modules folder, skip this — the dependencies are bundled and DSMT is ready to run offline. Otherwise, from the DSMT folder: 

    npm install --omit=dev

  3. Start the server

    npm start

    You should see:

    DSMT v0.1.0 listening on http://127.0.0.1:8080

  4. Open the wizard

    Browse to http://127.0.0.1:8080 on the machine running DSMT. You will land on the setup wizard. Work through section 4.

  5. Run it as a service (optional)

    npm start stops when you close the terminal. To keep DSMT running, register it as a Windows service with a tool such as NSSM, or as a systemd unit on Linux. Point the service at node server/index.js with the DSMT folder as its working directory.

Verify the install (optional)

The unit tests need no database and no domain controller:

npm test

4. The setup wizard, field by field

The wizard has four steps. You cannot move past a step until its Test connection button has succeeded — and if you edit a field afterwards, that pass is revoked and you must test again. This is deliberate: the final Review screen can then never describe settings that were never verified.

Step 2 — Database

FieldWhat to enter
Server The SQL Server hostname or IP — sql01.contoso.local. You can also paste sql01,1433 or sql01\SQLEXPRESS straight from SSMS; DSMT splits it into the fields below when you leave the box.
Port Defaults to 1433. Disabled when an instance name is set.
Instance name Only for named instances, e.g. SQLEXPRESS. Leave blank otherwise. A named instance is resolved by the SQL Browser service, so it cannot be combined with a port — DSMT disables the port box when you fill this in.
Authentication SQL Server Authentication or Windows Authentication (NTLM).
Username / Password Optional. Leave both blank and DSMT connects as the Windows account it is running as — the wizard shows you which account that is. Otherwise enter a SQL login, or DOMAIN\user with Windows Authentication (NTLM) selected. Filling in only one of the two is treated as a mistake and rejected.
Database name The database DSMT creates and keeps its configuration in — DSMT by default. Letters, digits and underscores only, starting with a letter. If it already exists, DSMT adopts it and adds any missing tables; nothing is ever dropped.
Trust the server certificate Tick this if SQL Server uses a self-signed certificate.

Press Test connection first. DSMT reports the SQL Server version, which login it connected as, and whether that login can create a database — so a missing dbcreator role shows up now rather than at the next button. Then press Create database.

Connecting as the account DSMT runs as

Leaving both credential boxes empty selects Windows Integrated Authentication: no credentials are sent, and SQL Server authenticates the DSMT process by its own Windows token. This is usually the cleanest option on a domain-joined server — there is no second password to store or rotate.

  • Grant that account a SQL Server login with the dbcreator role.
  • If you run DSMT as a Windows service, the relevant account is the service's Log On As identity, not the person who installed it.
  • It requires the msnodesqlv8 driver. Recent release packages bundle it; if the wizard reports it is missing, run npm install msnodesqlv8 in the DSMT folder and restart.
  • Windows only. On Linux or macOS, enter a SQL login instead.
The directory step still needs a bind account

Integrated authentication applies to SQL Server only. DSMT's LDAP client cannot present the process's Windows identity to a domain controller — that would need Kerberos/SSPI, which it does not support — so the domain step requires an explicit username and password.

Step 3 — Directory

FieldWhat to enter
Domain controller Hostname or IP of a DC — dc01.contoso.local.
Port 389 for LDAP, 636 for LDAPS. Ticking the LDAPS box moves it for you. A port you typed yourself is preserved — useful for the global catalog on 3268 / 3269.
Use LDAPS Encrypts the connection. Requires certificates on your domain controllers.
Trust the server certificate Only shown with LDAPS on. Tick it when the certificate comes from an internal CA that this server does not trust — the common case.
Domain name Your AD domain, contoso.local — not the controller's hostname. DSMT builds the base DN from it.
Base DN Filled in from the domain: contoso.local becomes DC=contoso,DC=local. Edit it to search a single OU instead, e.g. OU=Staff,DC=contoso,DC=local — once you type your own, DSMT stops overwriting it.
Username The bind account, in any of three forms: CONTOSO\svc_dsmt, svc_dsmt@contoso.local, or a full DN such as CN=svc_dsmt,OU=Service,DC=contoso,DC=local. A bare username is completed using the domain above. Non-AD LDAP servers usually need the full DN.
Password Stored encrypted with AES-256-GCM and never sent back to the browser.

Test connection reports which server it actually reached and how many user accounts are visible under the base DN. If it says zero users, the base DN is almost certainly pointing at a container that holds none.

Step 4 — Review and finish

Check the summary, then press Finish setup. DSMT re-verifies both connections, writes the configuration, and takes you to the user list.

5. Configuration reference

All optional. Set them in the environment before starting DSMT.

VariableDefaultPurpose
DSMT_PORT 8080 The port DSMT listens on.
DSMT_HOST 127.0.0.1 The interface to bind. Changing this exposes an unauthenticated tool — read section 9 first.
DSMT_SECRET_KEY generated Key material used to encrypt the stored bind password. If unset, DSMT generates a key file on first run and reuses it. Set this explicitly if you manage secrets centrally, or if DSMT runs on more than one host against the same database.

Windows

set DSMT_PORT=9000
npm start

Linux / macOS

DSMT_PORT=9000 npm start

6. Files DSMT creates

PathContents
server/data/bootstrap.json How to reach SQL Server, with the password encrypted. Written only after the database really holds the configuration, so an interrupted install never leaves DSMT pointing at a database that was never provisioned.
server/data/dsmt.key The generated encryption key, created with owner-only permissions. Not used when DSMT_SECRET_KEY is set.
Both files are secrets

Together they give up the bind account's password. Back them up somewhere safe, restrict them to the service account, and keep them out of source control. Losing dsmt.key means re-running the wizard to re-enter the bind password; it does not lose any directory data.

In the database

TableContents
app_settingsSchema version and the setup-complete flag.
directory_configThe directory connection. The bind password is stored encrypted.
audit_logA record of configuration changes.

7. Troubleshooting

Every failure names its own cause and next step rather than saying "connection failed". Find the message you saw below.

SQL Server

MessageCause and fix
SQL Server not found The hostname did not resolve. Check the spelling, or use the IP address.
Named instance not found The SQL Browser service must be running on the SQL Server, with UDP 1434 open.
Could not reach SQL Server The instance is stopped, TCP/IP is disabled in SQL Server Configuration Manager, or the port is closed.
Connection timed out Almost always a firewall between this server and SQL Server.
SQL Server rejected the login Wrong credentials — or SQL Authentication is being used while the server is set to Windows-only. Enable mixed-mode authentication.
Cannot open that database The login is valid but has no access to that database. Grant it, or pick another name.
The account lacks permission Creating a database needs the dbcreator server role. Grant it, or create the database manually and re-test.
The SQL Server certificate was rejected Self-signed certificate. Tick Trust the server certificate.
Windows Integrated Authentication is unavailable You left the credentials blank, but the msnodesqlv8 driver is not installed — or DSMT is not running on Windows. Run npm install msnodesqlv8 and restart, or enter a username and password.
Incomplete credentials Only one of username/password was filled in. Complete both, or clear both to connect as the account running DSMT.
Invalid database name Use letters, digits and underscores, starting with a letter, up to 63 characters.

Directory

MessageCause and fix
Domain controller not found The hostname did not resolve. Check the spelling, and that this server uses the domain's DNS.
Connection refused Nothing is listening on that port. For LDAPS, port 636 must be open and a certificate installed on the DC.
Connection timed out A firewall, when the hostname itself resolves.
The LDAPS certificate was rejected An internal CA this server does not trust. Tick Trust the server certificate, or install the CA certificate on this machine.
The bind account was rejected Wrong username or password. Try DOMAIN\user or user@domain. A locked or expired account fails identically.
The base DN was not found The base DN does not exist in this directory. For contoso.local it is DC=contoso,DC=local.
The bind account lacks permission It connected but cannot read that part of the directory. Check for a restrictive ACL on the OU.
Connected, but no users were found The base DN points at a container holding no user accounts. Widen it to the domain root.

Other

MessageCause and fix
Setup has already been completed The wizard closes itself once setup finishes. See section 8 to re-run it.
DSMT is not configured yet No directory connection is saved. Run the wizard.
Cannot reach the DSMT server The Node process is not running, or the browser is pointed at the wrong port.
Too many attempts More than 30 setup requests in a minute. Wait a minute.

8. Re-running setup and upgrading

Re-running the wizard

Setup rewrites how DSMT connects to everything, so it refuses to run a second time. To point DSMT at a different database or directory:

  1. Stop DSMT.
  2. Delete server/data/bootstrap.json.
  3. Start DSMT and browse to it. The wizard runs again.

Keep server/data/dsmt.key unless you are also discarding the old database — the stored bind password cannot be decrypted without it.

Upgrading

  1. Stop DSMT.
  2. Back up server/data/.
  3. Extract the new release over the old folder.
  4. Run npm install --omit=dev if the ZIP has no bundled node_modules.
  5. Start DSMT. Schema changes are applied automatically and never drop anything.

Which files need what after a change

ChangedAction needed
*.html, assets/**Refresh the browser.
server/**Restart the Node process.

9. Security — read before exposing DSMT

There is no sign-in in this release

The sign-in page exists but is not connected to anything — its form does nothing when submitted. There is no login endpoint, no session, and no check on any page or API route.

Anyone who can reach DSMT's port can read every user in your directory, using the bind account's permissions. Before setup completes they could also point DSMT at a database and directory of their own choosing.

Keep DSMT_HOST on 127.0.0.1 until authentication ships. DSMT prints a warning at startup if you bind it anywhere else.

What is protected

  • The bind password is encrypted at rest with AES-256-GCM, and never sent to the browser.
  • Everything typed into a search box is LDAP-filter-escaped, so directory queries cannot be rewritten by input.
  • The database name is checked against a strict allowlist and bracket-quoted, because CREATE DATABASE cannot use a parameter.
  • Setup requests are rate limited, and setup closes permanently once complete.
  • DSMT never writes to Active Directory. Read access is all the bind account needs.

Recommended

  • Run DSMT as a dedicated low-privilege service account — and prefer Integrated Authentication for SQL Server, so no database password is stored at all.
  • Give the bind account read-only rights, and nothing more.
  • Use LDAPS so the bind password is not sent in the clear.
  • Restrict server/data/ to the service account.

10. What has and has not been tested

Stated plainly so you know where to look first if something misbehaves.

AreaStatus
Core logic — filter escaping, account-flag decoding, date conversion, DN parsing, connection building, encryption Covered by unit tests (npm test).
LDAP and LDAPS — connect, list, search, user detail, group membership, certificate handling, error reporting Verified against a live LDAP server, including a self-signed LDAPS certificate.
SQL Server — database creation and schema Not yet run against a real SQL Server. This is the most likely place to hit a problem on first install. If the wizard's database step fails in a way this guide does not explain, that is why.
Nested group membership (the Include nested groups toggle) Uses an Active Directory-specific feature that the test server did not support, so it is unverified. Check it early against your own domain.
Domains with more than 1000 users Paged searching is implemented but has not been exercised at that size.
